# 自動更新 vs 私有 repo

登入器的自動更新是這樣運作的：

1. 程式打 `https://api.github.com/repos/xense999/KZ-Login/releases/latest`，比對 tag 與自己的版號。
2. 有新版就下載 Release 上那顆**裸 exe**，寫成 `kz-login.new.exe`。
3. 把正在跑的 exe 改名成 `.old.exe`、新檔改名頂上，然後啟動新版、關掉自己（下次開機再清掉 `.old.exe`）。

**它能這樣做的前提是 `KZ-Login` 是公開 repo** —— 上面兩個網址都不需要任何憑證。
而 `kz-maplestory` 我剛照你的要求建成**私有**，這兩個網址都會回 404，程式收到的訊息會是「查不到更新」。

---

## 三條路

### A. 把 repo 改成公開（跟登入器一樣）
- 更新程式碼可以完全照抄登入器，最單純、最可靠。
- **代價**：程式碼會被任何人看到。這個專案裡沒有金鑰、沒有帳號密碼、沒有付費邏輯，
  唯一敏感的是「鍵盤 hook」這件事本身會攤在陽光下。

### B. 維持私有，把一組 GitHub token 編進程式裡
- 程式帶著 token 去問 API、去下載 asset。做得到，登入器沒這樣做但 kz-admin 有「金鑰編譯期注入」的先例。
- **代價一**：token 就在 exe 裡，會被挖出來。要用**細粒度、唯讀、只授權這一個 repo** 的 token 把傷害壓到最小
  （被挖走等於「這個 repo 被人看光」，跟 A 的結果一樣，只是慢一點）。
- **代價二**：token 有效期到了要重新發、重新打包，忘了就是全體使用者更新失效。
- **代價三**：token 要進 GitHub Actions 的 secret，我沒辦法幫你建，得你自己去設定頁面產生後貼上。

### C. 維持私有，不做自動更新
- 保留「檢查更新」以外的一切，發版時你自己把安裝檔給使用者。
- 這個工具如果只有你自己用，其實這條最省事。

---

## 我的建議：A（改公開）

理由是 B 的代價換不到實質的保密——token 遲早被挖出來，結果跟公開一樣，中間還多了一組會過期的東西要維護。
真的要保密就該連 Release 都不公開（C）；願意讓使用者自動更新，實質上就已經接受「二進位檔在外面」了。

如果你要的只是「不要被路人搜尋到」，公開 repo 但不宣傳其實就達成了。
