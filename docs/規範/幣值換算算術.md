# 幣值換算算術 — 模組規範

> 本模組契約的唯一 owner。

## 公開介面

- `W`、`YI`：楓幣的兩個級距常數（一萬、一億）
- `FEE_PERCENT_NORMAL`、`FEE_PERCENT_VIP`、`feePercent(vip)`：手續費率
- `fromNtd(ntd, rateW, vip)`：付這麼多台幣，實際入手多少楓幣
- `fromNet(net, rateW, vip)`：要入手這麼多楓幣，該付多少台幣
- `roundUpSuggestion(ntd, rateW, vip)`：付整數台幣的話要付多少、會多拿多少
- `formatMeso(meso)`：談價用的寫法（滿一億才進位的兩段式）
- `formatRaw(meso)`：原始數字，帶千分位
- `formatNtd(ntd)`：台幣的寫法（無條件進位到小數第 2 位）
- `mesoToText(meso)`：楓幣填回輸入欄時的寫法（楓幣本身，帶千分位）
- `mesoTextInWords(text)`：楓幣欄位的文字換成談價的級距
- `parseAmount(text)`：欄位文字轉數字（千分位一起貼進來也認得）

## 單一來源

- 手續費率（非 VIP 5%、VIP 3%）只在這裡寫一次
- 台幣↔楓幣的換算式只在這裡
- 楓幣與台幣的顯示寫法只在這裡——主頁、浮動面板、填回輸入欄的文字都呼叫同一支

## 不變量

- 金額的對外單位一律是**楓幣**；匯率的單位一律是 **W／台幣**
- `Deal.fee === Deal.face - Deal.net`
- `fromNet(fromNtd(n, r, v).net, r, v).ntd` 回到 `n`（浮點誤差內）
- 算不出來（匯率 ≤ 0、非數字、負金額）一律回 `null`，絕不回 `Infinity` 或 `NaN`
- 捨去方向是有意義的、兩邊相反：台幣**進位**（付的錢不能比算出來的少），
  楓幣**捨去**（不能顯示成比實際拿得到的多）
- `formatNtd` 顯示成整數的那一刻，`roundUpSuggestion` 一定回 `null`——
  畫面上不能一邊寫「2.00 元」一邊建議「付 3 台幣」

## 禁止

- 不 import Vue、Pinia 或 Tauri —— 正面做法：這裡只收數字、只回數字與字串，狀態放 `幣值換算狀態`
- 不用 `toLocaleString` 做千分位 —— 正面做法：自己分組，輸出不跟著系統地區變
- 費率不寫成 `0.05` 這種小數 —— 正面做法：用整數百分比再除 100，常見金額才落在整數上
- 楓幣的零頭不進位 —— 正面做法：無條件捨去，否則 `9,999.9999W` 會顯示成看起來像一億
